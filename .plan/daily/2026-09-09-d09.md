## 关键设计决定

- `OAuth2PasswordBearer` 负责从 Authorization Bearer 头提取 token，并在缺失或格式错误时短路返回 401。
- JWT 验签保持无状态、不查库；`/me` 再按 subject 查库，是为了物化用户资料并阻止已删除用户继续访问。
- 过期、无效、缺失 token 都属于未认证，统一使用 401；403 留给后续权限控制场景。
- `UserOut` 显式限制公开字段，响应不会包含 `hashed_password`。

### 老师讲解 / 我的复述记录

**学生三题作答（带教中）**：
1. **已删用户的 token 不能再用** —— ✅ 正确，并准确指出由 `deps.py:45-47` 的 `db.get` 查空拦截。
2. **依赖注入** —— ⚠️ 三处偏差：(a) 误以为存在「服务端**会话 id**」（本项目是 JWT 无状态，**全程无 session**；token 里的 `sub` 是 user id）；(b) 顺序说反（以为「先调 `get_current_user`，再回头发现它的依赖」）；(c) 把 DI 的价值窄化为「为了不重复写代码」。
3. **加保护** —— ⚠️ 把「**认证**」说成了「**权限**」（原话「就不给予它权限」），且未点出「加保护 = 加一行 `Depends`」这一真正价值。

**老师纠偏要点**：
1. **DI 的机制 = 角色反转**。路由函数不是浏览器调的、是 **FastAPI 调的**；框架作为调用方，才有资格在调用前替你把参数准备好。`Depends(get_current_user)` 的语义就是一句：「这个参数我不管，你去跑 `get_current_user()`，把返回值塞进来。」
2. **顺序 = 先扫签名（自上而下），再执行（自底向上）**。扫 `read_current_user` → 扫 `get_current_user` → 扫 `oauth2_scheme` / `get_db`，画出依赖树——**此时一个函数都还没跑**；然后叶子先跑：`oauth2_scheme` 剥 token（剥不到即 401）→ `get_db` 开会话 → `get_current_user`（参数这时才齐）→ 最后 `read_current_user`。**依赖短路**：401 之后其余函数一个都不执行，这正是 `/me` 函数体里没有任何 `if` 的原因。
3. **Session 不是「记录操作的日记」**，是一次请求的**草稿纸 + 事务边界**：多个 DB 操作先攒在 Session 里 → `commit()` 才落库 → `finally: db.close()` 把连接还给池。此处 `db.get` 只是读，连草稿都没写。
4. **`get_current_user` 返回的是 `User`（ORM 对象，身上带着 `hashed_password`），不是 `UserOut`**；是 `response_model=UserOut` 在**出厂最后一刻**按白名单过滤。**安全防线在 schema，不在 router 的自觉。**
5. **DI 的三个真实价值**：① 关注点分离（路由完全不懂 token 从哪来、怎么验）② 可组合（依赖套依赖，将来写 `get_current_admin` 直接复用验签）③ 可替换（`app.dependency_overrides` 让测试能伪造登录态，M4/M5 会用到）。
6. **认证 vs 授权**：401 = 你没证明你是谁；403 = 知道你是谁但你没资格。D09 三处失败出口（过期 / 无效 / 已删）**全是 401**，403 一个不造。
7. **`nickname` = 展示名**（可空、可改、不要求唯一），与 `username`（登录凭据、唯一、一般不给改）职责不同——「用于登录的名字」和「用于显示的名字」是两件事。注册接口暂不收集，故为 `None`。

**最终链路（定稿，明日费曼依据）**：
请求带 `Authorization: Bearer <token>` → FastAPI **扫签名画依赖树** → **自底向上执行**：`oauth2_scheme` 剥 token（无 / 格式错 → 立即 401 **短路**）→ `get_db` 开工作单元会话 → `get_current_user` 验签 + 查过期 + 查 `sub`（**无状态、不查库**）→ `sub` 转 int → `db.get(User, id)` **物化主体**（查不到 = 用户已删 → 401）→ 路由 `read_current_user` 只 `return User` → `response_model=UserOut` **白名单序列化** → 200 JSON（无 `hashed_password`）。
