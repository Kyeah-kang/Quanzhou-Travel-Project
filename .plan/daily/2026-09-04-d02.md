## 复盘过程（关键认知纠偏——Navicat 不存数据）
学生起初困惑「难道还有非本机 MySQL？Navicat 里不就存着数据库吗」→ 澄清：
- MySQL = **服务端引擎(mysqld)**，数据在磁盘数据文件里，占 3306 等你连。
- Navicat = **客户端/遥控器**，不存数据，只连某台引擎查看。
- 旧项目数据实际在**原生 Windows MySQL 服务(MySQL82)** 里，Navicat 填 `127.0.0.1:3306` 连到它。
- Docker 容器 mysql 是**同机另一套引擎实例**，也要 3306 → 冲突根因。
- 结论：停原生则容器占 3306（Navicat 无缝改连新库）；或容器让到 3307 两套并存。

## 学生决策
保留原生 MySQL82（旧项目在用、习惯 Navicat）→ **容器 mysql 改 3307:3306，两套并存**。
已记入 CLAUDE.md §10 决策日志：**M1 起 backend 连本库用 127.0.0.1:3307**。

## 复盘要点（明早费曼核对）
1. **镜像 vs 容器**；为什么「数据库也用容器跑」——本机原生 mysqld 抢 3306 就是活案例。
2. compose 端口映射 `HOST:CONTAINER`；冲突发生在 **host 侧**。
3. healthcheck 为何用 `$$` 而非 `$`。
4. 命名卷数据在哪、为什么删容器不丢数据。
5. Navicat 是客户端不是数据库；换引擎不改用法，只改连的地址/端口/密码。
