## 关键设计决定

- `site_key` 是幂等 upsert 的判定键；MySQL 的 `source` 只保存首项短引文，完整列表留给语料和 PG metadata。
- 行程约束字段允许为空，不能为了完整率伪造事实；可得字段与待校对字段分开统计。
- `key_element`、`fact_status`、`pending_fields` 一并落 MySQL，保留“暂定归类”和待校对边界，不把编辑归类误当成史实核验。
- loader 只在字段值实际变化时统计 `updated`，使用 SQLAlchemy ORM 比较 JSON 列表，不依赖更新时间字段判断。

### 请 Codex 修改（1 项，必修）

**① `_source_short` 的 `strip("《》")` 把结尾书名号吃掉了 —— 22 行 `source` 全部残缺**（`backend/app/ingest/site_loader.py:39`）
- **老师实测**：`_source_short()` 返回 `'泉州市人民政府《安平桥-全国重点文物保护单位简介'`；查库确认**已落库**：
  `anping_bridge -> '泉州市人民政府《安平桥-全国重点文物保护单位简介'`
  `caoan_manichaean_statue -> '泉州市人民政府《草庵摩尼光佛造像：世界仅此一尊'`
- **根因**：`f"{publisher}《{title}》".strip("《》")` —— `str.strip()` 会从**两端**删除所有属于字符集 `{《, 》}` 的字符，**结尾的 `》` 必然被删**。附带：若 `publisher` 为空，开头的 `《` 也会被删。
- **为什么必修**：这是**落进数据库的产品数据**，M4 前端「资料来源」会直接显示残缺书名号；且 22 行全中招。属于「数据事实被静默改坏」，与语料保真同一条红线。
- **修法建议**：不要对拼接结果整体 strip。改为先各自 strip 再拼（保留书名号），例如
  `f"{publisher}《{title}》" if publisher else f"《{title}》"`；对 `title` 为空的情形另作处理。
  **补回归测试**：断言 `_source_short()` 的结果**以 `》` 结尾**、且含成对的 `《…》`。

### 其余发现（低）

**② 完整率表走 stderr，与简报「打印到 stdout」的要求相反**（`site_loader.py:96-104`、`:129`）
- **老师实测**：`STDOUT 含完整率表: False`；`STDERR 含完整率表: True`。即 `python -m app.ingest.site_loader > out.txt` **拿不到完整率表**。
- 根因：`logging.basicConfig()` 未指定 `stream`，默认写 `sys.stderr`。
- 加剧因素（非本日引入）：`settings.debug=True` → `engine(echo=True)`，**SQL 回显占据 stdout**（实测 stdout 18.5 KB 全是 SQL）。
- 修法：`_print_completeness` 改 `sys.stdout.write`，或显式 `logging.StreamHandler(sys.stdout)`。

**③ 异说块里的 `**` 加粗被去掉（46 处中的 7 处）**
- 机器比对：**事实文字逐字相同**，仅少了 `**…**` 强调标记。属格式差异，**不构成保真违规**，但简报要求「整段原样」，登记备查。

**④ `main()` 恒返回 0**（`site_loader.py:137`）——与 `corpus_check.main()` 的退出码语义不一致。但解析失败时 `iter_corpus_documents` 会直接抛异常（**管线快速失败**，符合 M2 决策 D9 的既定分工），实际不会"静默成功"。**仅登记，可不改。**

**⑤ `_is_pending` 与 `_is_blank` 口径不一致**（`site_loader.py:110` vs `corpus_check.py:110`）：前者认 `[]` 为待校对、但**不认 `""`**；后者认 `""`。目前数据不会触发，属潜在分歧。
