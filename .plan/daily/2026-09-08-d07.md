## 今日目标

- 只用 username 登录并签发 JWT，不实现 token 解码和受保护路由。
- 登录失败统一返回 401，避免通过响应区分用户名是否存在。
- token 只携带 `sub` 和 `exp`，密钥从本地 `.env` 读取。

## 今日产出

- 增加 `LoginIn`/`LoginOut`，登录只接受 username 和 password。
- 增加 `auth_service.login`，查询用户、复用 bcrypt 校验并签发 token。
- 增加 `create_access_token`，JWT payload 只有 `sub` 和 `exp`。
- 增加严格的 `SECRET_KEY` 配置，缺失或长度不足时配置校验失败。
- 暂不实现 token 解码、鉴权依赖和 `/me`，留给 D08/D09。

## 关键设计决定

- REST 登录返回无状态 token，避免服务端 session 在多实例间共享；代价是 token 在过期前不能即时吊销，后续再讨论。
- 用户不存在与密码错误统一为同一 401，避免通过响应枚举用户名。
- token 不携带密码或其他敏感信息，密钥只来自本地 `.env`，不写代码、不进日志。

### 老师讲解 / 我的复述记录
**学生复盘原话要点**（老师纠偏前）：注册=Schema 校验+哈希存库；登录=校验用户名/密码；登录后浏览器签发 token 携带即可免重复登录；链路=Schema→Router→Service。

**老师纠偏 4 点**：
1. token 由**服务端**签发，不是浏览器；浏览器只是保存+携带
2. token **有时效**（30 分钟），过期需重新登录/刷新，非"登录一次永久"
3. 盐**内嵌在哈希串里**（`$2b$12$...`），不是"在哈希前"；验证=取盐→重算明文→比对
4. 分层归属：查"库里有没有这用户"是 **Service** 的活，Schema 只校验**格式**；Router 是入口/翻译官，不写业务

**最终链路（定稿，明日费曼依据）**：
- 注册 = Schema 校验格式（422 挡下不合格）→ Router(入口) → Service：查重(有则409) + bcrypt哈希 + 存库 → RegisterOut 白名单返回（哈希不外泄）
- 登录 = Schema 校验格式 → Router → Service：查 username（无则401）+ verify_password（取盐重算比对）→ 匹配则服务端签发 token(sub+exp, SECRET_KEY签名) → LoginOut 返回
- 三层一句话：Schema 管格式校验+序列化白名单（不碰DB）；Router 管入口+异常翻译成 HTTP 状态码；Service 管真业务（查库/比密码/签发）
