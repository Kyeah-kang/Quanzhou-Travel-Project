## 今日目标

- 只用 username 登录并签发 JWT，不实现 token 解码和受保护路由。
- 登录失败统一返回 401，避免通过响应区分用户名是否存在。
- token 只携带 `sub` 和 `exp`，密钥从本地 `.env` 读取。

## 今日产出

- 增加 `LoginIn`/`LoginOut`，登录只接受 username 和 password。
- 增加 `auth_service.login`，查询用户、复用 bcrypt 校验并签发 token。
- 增加 `create_access_token`，JWT payload 只有 `sub` 和 `exp`。
- 增加严格的 `SECRET_KEY` 配置，缺失或长度不足时配置校验失败。
- 暂不实现 token 解码、鉴权依赖和 `/me`，留给 D08/D09。

## 关键设计决定

- REST 登录返回无状态 token，避免服务端 session 在多实例间共享；代价是 token 在过期前不能即时吊销，后续再讨论。
- 用户不存在与密码错误统一为同一 401，避免通过响应枚举用户名。
- token 不携带密码或其他敏感信息，密钥只来自本地 `.env`，不写代码、不进日志。
