## 二、本模块要解决什么问题 / 教学点
D07 会发 token、D08 会验 token，但 token **还没用来拦任何接口**——现在的接口全是裸奔。D09 把「验 token」升级成 FastAPI 的**认证依赖注入**，并加第一个受保护接口 `GET /api/auth/me`（返回当前登录用户资料），从此鉴权链路完整闭环，且以后任何接口想加保护只需一行 `Depends(get_current_user)`。
教学点（老师精讲、代码落地到 deps.py）：① **依赖注入是什么**：FastAPI 看到 `Depends(...)` 就自动去调那个函数拿参数，路由函数根本不管 token 从哪来——「我要一个当前用户」，框架去取；② **OAuth2PasswordBearer** 替你做了三件事：从 `Authorization: Bearer <token>` 头里取 token、没给头/头格式错就直接 401 + `WWW-Authenticate`、把 token 字符串作为依赖注入；③ **鉴权链路完整复述**：HTTP 头 → oauth2_scheme 提取 token → `decode_access_token` 验签（无状态、不查库）→ 按 sub 查库拿 User（物化主体，防已删用户）→ 注入路由 → 返回 UserOut；④ **401 vs 403 纠偏**：过期/无效/缺失 token 都是「没认证」→ **401**（带 `WWW-Authenticate: Bearer`）；403 是「已认证但没权限」，留给以后的角色/越权场景——修正 D08 那句「过期 401 / 无效 403」的说法，本课讲清楚；⑤ **依赖短路**：鉴权失败时 FastAPI 直接返回，路由体不执行；⑥ **敏感不出 schema**：`UserOut` 显式列字段，`hashed_password` 永不进响应。

## 四、交付物与验收

### deps.py 提供
```python
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/auth/login")

def get_current_user(
    token: Annotated[str, Depends(oauth2_scheme)],
    db: Annotated[Session, Depends(get_db)],
) -> User:
    """验 token → 查用户 → 返回当前登录用户；失败统一 401。"""
```
- `decode_access_token` 抛的 `TokenExpiredError` → `HTTPException(401, "登录已过期，请重新登录")`
- `TokenInvalidError`（含 sub 非数字转 int 失败）→ `HTTPException(401, "无效的访问令牌")`
- 手动抛 401 都带 `headers={"WWW-Authenticate": "Bearer"}`
- token 验过但 `db.get(User, user_id)` 查不到（用户已删/不存在）→ 401「用户不存在或已被删除」
- 注释讲清：验签**无状态不查库**；查库只是为了**物化主体 + 防已删用户**——这是 D08「验签不查库」与「/me 要用户资料」的和解点

### auth.py 增加
```python
@router.get("/me", response_model=UserOut)
def read_current_user(current_user: Annotated[User, Depends(get_current_user)]) -> UserOut:
    """返回当前登录用户资料。"""
    return current_user
```
- router 仍瘦：无 SQL、无业务，主体由依赖注入

test_me.py 至少覆盖（沿用 test_login 的 register/login 造真实用户 + SessionLocal 清理模式）：
- **无 token** 调 /me → 401
- **坏 token**（乱串/被篡改签名）→ 401
- **过期 token**（jwt.encode 造 exp=过去）→ 401，detail 提示过期
- **合法 token** → 200，返回该用户 id/username/email，且响应**不含** hashed_password
- **用户已删**：注册→login 拿 token→直接删用户行→调 /me → 401（防已删用户）
