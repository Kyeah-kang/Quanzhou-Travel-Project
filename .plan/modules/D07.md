## 二、本模块要解决什么问题 / 教学点
实现登录：验身份 → 返回 **无状态 token**，并讲清**为何 REST 用 token 而非服务端 session**。
教学点：① **session vs token 的取舍**（服务端存会话/内存放大/多实例要共享/移动端与前后端分离；token 自带信息、无状态、可跨实例——以及它的代价：不可即时吊销、泄露要等过期）；② 登录失败为何一律回**同一句 401**（防用户名枚举）；③ `verify_password`（D06 留的钩子）真正上岗；④ token 里只放**最小必要声明**（sub=user id、exp），不放密码；⑤ 密钥只从 `.env` 来、绝不硬编码/入库。
> 边界约定（避免与 D08 撞车）：D07 只做「签发 token（create）」，返回 JWT 字符串即可；**JWT 的 decode/verify 工具 + Header.Payload.Signature 拆解精讲留到 D08**（D09 的 `/me` 会用）。

## 四、交付物与验收

### 接口契约
- `POST /api/auth/login`，body `LoginIn`：`username`(str) + `password`(str)
- 成功：**200** `LoginOut`：`access_token`(str) · `token_type="bearer"` · `expires_in`(秒)
- 失败（用户不存在 **或** 密码错）：**401**，detail 统一 `"用户名或密码错误"`（不区分，防枚举）

### 实现要点
- `config.py`：`jwt_secret: str`、`jwt_algorithm="HS256"`、`access_token_expire_minutes: int = 30`；`.env` 的 `SECRET_KEY` 若缺省则启动报错兜底（或强默认仅限 dev——二选一，注释说明）
- `security.py::create_access_token(subject: str | int, ...) -> str`：`payload={"sub": str(subject), "exp": now+timedelta(minutes=…)}`；`jwt.encode(payload, settings.jwt_secret, algorithm=settings.jwt_algorithm)`
- `auth_service.py::login(db, data) -> str`：`select(User).where(User.username==…)` → 无用户抛 `InvalidCredentialsError`；有则 `verify_password(data.password, user.hashed_password)` 不过抛同一异常；过则返回 `create_access_token(user.id)`
- `routers/auth.py::POST /login`：瘦——`Depends(get_db)`，调 service，`InvalidCredentialsError` → `HTTPException(401, "用户名或密码错误")`；`response_model=LoginOut`
- schema：`LoginOut` 的 `token_type: str = "bearer"`、`expires_in` 可由 `access_token_expire_minutes*60` 填（可在 router/service 组装常量）

### 依赖
`pyjwt>=2.8,<3.0`。装进 pyproject dependencies。
