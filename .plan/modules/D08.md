## 二、本模块要解决什么问题 / 教学点
D07 会"发"（签发），D08 学"验"（解码），把 JWT 这半条命补全；D09 用解码器做受保护路由。
教学点（老师精讲、代码落地到 security.py）：① JWT 三段结构 `Header.Payload.Signature`：base64url 编码可**肉眼解出明文**（所以**绝不放敏感数据**），安全靠的是签名；② 签名 = HMAC-SHA256(header.payload, SECRET_KEY)——**验签不查库**（无状态的真义）；③ 验签四件事：签名对不对、`exp` 有没有过、`sub` 在不在、**只认配置里的算法**（防 `alg=none`/算法混淆攻击）；④ 过期 vs 无效要区分（未来 401/403 语义不同）；⑤ 只信任服务端密钥，任何客户端都改不了 payload（改了签名就破）。

## 四、交付物与验收

### security.py 增加
```python
class TokenError(Exception): ...        # 无效基类
class TokenExpiredError(TokenError): ... # 过期（区分用）
class TokenInvalidError(TokenError): ... # 签名错/结构坏/算法不符等

def decode_access_token(token: str) -> str:
    """验签+查过期+查 sub，返回 subject(user id 字符串)。"""
```
- 用 `jwt.decode(token, settings.jwt_secret, algorithms=[settings.jwt_algorithm], options={"require": ["exp", "sub"]})`
- 异常映射：`jwt.ExpiredSignatureError` → `TokenExpiredError`；其余 `jwt.InvalidTokenError`（含 InvalidSignatureError/DecodeError/InvalidAlgorithmError）→ `TokenInvalidError`；缺 `sub`/`exp`（require 不满足）→ `TokenInvalidError`
- 返回 `payload["sub"]`；**不打印 token/不打印异常内容里的 token**
- 注释讲清为何 `algorithms` 列表写死配置算法（防算法混淆）

### 验收（在 backend/.venv 激活后执行，贴真实输出）
```
python -m ruff check .
python -m pytest -q                    # 原 11 条 + test_token.py
```
test_token.py 至少覆盖：
- 合法 token（D07 签的）decode → 返回对应 sub 字符串
- **过期** token（自造 exp=过去 1s 的合法签名 token）→ `TokenExpiredError`
- **篡改**：改动签名/头部任一字 → `TokenInvalidError`
- **错误密钥** 签的 token → `TokenInvalidError`
- 缺 `sub`（如只 `{exp}`）→ `TokenInvalidError`
> 造过期/坏 token 直接在测试里用 `jwt.encode` 拼，不走 `create_access_token`（它永远给未来时间）。测试可用固定 secret 但建议走 `settings.jwt_secret`。
