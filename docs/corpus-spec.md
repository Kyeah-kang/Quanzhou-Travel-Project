# 刺桐智游语料合同 v2

本文定义 `data/raw_md/` 中站点语料的 frontmatter、正文结构、来源标注和两个下游消费者的字段契约。D12–D19 的数据工程以本文为准。

## 1. 文件与正文

- 一个遗产点对应一个 Markdown 文件，文件名使用小写英文蛇形。
- `site_key` 等于文件名去掉 `.md` 后的值；主题语料使用 `topic_*` 前缀。
- 每篇站点语料必须按以下顺序包含六个一级标题：
  `概述`、`历史沿革`、`遗产价值`、`看点与细节`、`实用信息`、`常见问答`。
- 固定标题让 D16 可以按语义边界切分；FAQ 问答对也是适合检索的天然单元。

## 2. 字段分类

### 事实字段

以下字段需要可靠来源：

`name`、`alias`、`category`、`key_element`、`area`、`lat`、`lng`、`address`、`open_hours`、`visit_duration_min`、`notice`。

没有可靠来源时，数值字段填 `null`，文本字段填 `待校对`，并将字段名写入 `pending_fields`。`key_element` 即使有暂定归类，只要尚未核对申遗文本，也必须列入 `pending_fields`。

### 编辑归类字段

`theme` 和部分 `tags` 用于检索及行程主题匹配，不要求逐项来源，但必须遵守受控词表。编辑归类不能替代事实来源。

### 派生与元数据字段

`site_key`、`source`、`fact_status`、`updated` 用于文件定位、溯源和质量管理。

## 3. 字段消费者分工

同一份 frontmatter 同时服务结构化主数据和非结构化检索元数据：

| 字段 | MySQL `heritage_sites` | PG `documents.metadata` | 用途 |
|---|---|---|---|
| `site_key` | 唯一键 | `doc_key` | 站点标识、硬过滤 |
| `name` / `alias` | 是 | 是 | 展示、别名检索 |
| `area` | 索引 | 是 | 区域筛选、就近分组 |
| `category` / `key_element` | 分类字段 | 是 | 分类筛选、主题分组 |
| `lat` / `lng` | 是 | 是 | 地理就近 |
| `open_hours` | 是 | 是 | 行程硬约束 |
| `visit_duration_min` | 是 | 是 | 时间预算约束 |
| `theme` | 是 | 是 | 行程主题匹配 |
| `notice` | 是 | 是 | 游览提示 |
| `tags` / `intro_short` | 是 | 否 | 列表展示、轻量筛选 |
| `source` | 仅保存短引文 | 保存完整列表 | 引用溯源 |
| `fact_status` / `pending_fields` | 是 | 是 | 可信度标注、质检统计 |

MySQL 只存短引文，完整来源列表留在语料和 PG metadata，避免两处长文本口径漂移。

## 4. 受控词表

- `category`：港口码头、桥梁、航标塔、城市遗址、管理机构、文教建筑、宗教建筑、墓葬、石刻、窑址、冶铁遗址
- `key_element`：机构保障、多元社群、城市结构、生产基地、交通网络、整体格局
- `theme`：海丝溯源、宗教多元、古建桥梁、非遗体验、城市漫步、亲子研学
- `fact_status`：已核对、待校对

「文教建筑」是本版新增类别，因为泉州府文庙无法准确归入原有类别。`key_element` 属事实字段，下面的 22 处初步映射中尚未核到申遗文本原文的项目必须在正式语料中保持待校对。

## 5. 溯源与异说

每篇语料必须有非空 `source` 列表，每项至少包含 `title`、`url` 和 `accessed`。`accessed` 使用 `YYYY-MM-DD`。

`fact_status: 已核对` 时，`pending_fields` 必须为空；`fact_status: 待校对` 时，必须明确列出仍待核对的事实字段。校验器还会检查空值事实字段是否进入 `pending_fields`。

同一事实存在不同来源时，两个说法都保留，使用统一格式：

```text
> ⚠️ 异说：A 来源作 X，B 来源作 Y，以官方公布为准（待校对）
```

本日三个样例中，`key_element` 是老师按语义做的暂定归类，尚未核到申遗文本原文，因此虽有值仍列入 `pending_fields`，这是“暂定值”与“已核对事实”的区别。

## 6. 校验边界

`python -m app.ingest.corpus_check` 只检查结构，不判断史实真伪。它负责检查：

- 必填字段和字段类型
- `site_key` 与文件名一致
- 数值字段格式及正值约束
- 来源列表结构和日期格式
- 受控词表
- `pending_fields` 自洽关系
- 六个正文一级标题及其顺序

内容长度、重复率、术语一致性和事实层质量属于 D15 的内容质检，不在本校验器职责内。
